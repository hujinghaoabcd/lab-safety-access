# 安全审查与整改状态

## 结论

原始项目适合作为原型，但不应直接暴露到公网。首轮整改已修复身份认证、管理员权限、密码存储、敏感备份暴露和上传边界等最高优先级问题，并建立可验证、可选择启用的部署链路。

自动部署框架已经具备，但在依赖升级和回归测试完成前，不建议将 `AUTO_DEPLOY_ENABLED` 设置为 `true`。

## 已修复（P0）

### 身份认证与权限

- JWT 密钥不再写入源码；生产环境缺少或使用过短密钥时，服务拒绝启动。
- 管理员账号和密码改由服务器环境变量提供。
- 管理员登录签发真实 JWT，包含 `role=admin`，并限制签发方、算法和有效期。
- 除管理员登录外，全部管理接口要求有效管理员令牌。
- 学生与管理员登录增加基础速率限制。

### 密码

- 新建、导入、重置和修改的学生密码使用 Node.js `scrypt` 哈希。
- 旧数据库中的明文密码仅在首次成功登录时兼容验证，并立即原地升级为哈希。
- 新密码和默认初始密码至少 8 位。

### 敏感操作和文件

- 数据库备份不再通过公开静态目录提供。
- 备份下载改为需要管理员 JWT 的接口。
- 数据库清空与恢复默认关闭，仅在服务器明确设置 `ALLOW_DANGEROUS_DB_OPERATIONS=true` 时开放。
- SQLite 恢复文件检查扩展名、大小和文件头。
- Excel、PDF 和头像上传增加类型、大小和文件名限制。
- 修复考试记录导出路由被参数路由抢先匹配的问题。
- 当前分支删除了疑似学生名单的 Excel 文件，并提供匿名导入模板。

### 生产边界

- Express 关闭技术栈响应头，并增加基础安全响应头。
- 请求体大小受限，生产 CORS 改为显式允许列表。
- 增加健康检查、非 root 后端容器和持久卷。
- GitHub Actions 在部署前验证后端语法、前端构建和 Compose 配置。

## 仍需解决（上线阻塞）

### 1. 依赖漏洞

当前三个子项目的锁文件长期未更新。CI 中的 `npm audit` 已发现高危和严重漏洞，其中包括后端原生 SQLite 构建链、旧版文件上传组件、Excel 解析库，以及前端 HTTP/PDF/构建依赖。

处理原则：

1. 不执行未经审查的 `npm audit fix --force`；
2. 分模块升级并运行功能回归；
3. 对无修复版本的 Excel 解析库进行替换评估；
4. 先处理运行时依赖，再处理仅开发环境使用的构建依赖；
5. 修复完成后把关键级别审计改为阻塞 CI。

### 2. 自动化测试缺失

目前 CI 能证明代码可解析、前端可打包、Compose 可解析，但不能证明业务正确。至少需要补充：

- 学生和管理员登录测试；
- 无权限访问管理接口应返回 401/403；
- 密码明文到哈希的兼容迁移；
- 考试提交、判分、证书签发；
- 用户导入和题库导入；
- 数据库备份下载和危险操作开关；
- 前端核心登录及考试流程的浏览器测试。

### 3. 数据库迁移和恢复机制

数据库初始化代码直接检查和创建表，缺少版本化迁移。数据库恢复仍依赖替换 SQLite 文件和重启服务。后续应引入：

- `schema_migrations` 版本表；
- 有顺序、可重放的迁移脚本；
- 升级前自动备份；
- 恢复文件完整性检查；
- 维护窗口和恢复演练。

### 4. 敏感文件的 Git 历史

从当前文件树删除 Excel 不会删除历史对象。如果该文件含真实姓名、学号、手机号、邮箱或密码，应：

1. 立即确认文件内容和暴露范围；
2. 使用 `git filter-repo` 清理历史；
3. 强制推送所有受影响分支和标签；
4. 通知协作者重新克隆；
5. 对文件中出现过的密码或其他凭据进行更换。

### 5. 浏览器令牌存储

现有前端仍将 JWT 保存到 `localStorage`。首轮整改保留该方式以避免大范围接口兼容修改，但它会扩大 XSS 后果。后续建议改为：

- `HttpOnly`、`Secure`、`SameSite` Cookie；
- CSRF 防护；
- 短期访问令牌与服务端可撤销会话；
- 更严格的内容安全策略。

- 管理操作审计日志；
- 令牌迁移到安全 Cookie。

- 拆分过大的前端资源包；
- 统一 API 类型和输入校验；
- 将体量过大的控制器拆分为服务和仓储层；
- 增加端到端测试和可观测性。
