# 核心功能、数据一致性与测试审查

## 审查结论

项目已具备学生学习、考试、成绩、证书以及后台管理的完整原型，但原始实现缺少稳定的领域约束和自动化回归测试。主要风险不是页面样式，而是同一个操作可以从不同接口绕过、考试成绩与历史记录可能不稳定、学生可修改影响权限的身份字段，以及部分管理按钮没有真实后端功能。

本轮优先修复核心正确性。UI 与视觉一致性将在核心接口稳定后单独处理。

## 本轮修复

### 1. 公共接口越权

原 `/api/banner` 和 `/api/announcement` 路由同时公开了查询和管理操作。未登录访问者可以直接创建、修改或删除轮播与公告。

整改后：

- 公共路由只保留学生端读取接口；
- 所有增删改操作只保留在 `/api/admin/*`；
- 管理接口统一要求有效的管理员 JWT。

### 2. 考试访问与次数规则

考试详情、开始考试和提交考试原本没有使用同一套权限规则，用户可以绕过前端直接提交未发布、超出发布范围或已达到次数限制的考试。

整改后统一校验：

- 用户存在且账号启用；
- 考试存在并已发布；
- 用户院系和班级符合发布范围；
- 未超过最大尝试次数；
- 已通过的考试不能重复提交；
- 未配置题目的考试不能开始或发布。

最大尝试次数默认是 3，可通过 `MAX_EXAM_ATTEMPTS` 配置为 1–20。

### 3. 判分与证书

原算法按 `floor(总分 / 题数)` 逐题累计。总分 100、题目 3 道时，即使全部答对也只能得到 99 分。

整改后：

- 采用 `round(正确题数 / 实际题数 × 总分)`；
- 满分作答一定得到配置的总分；
- 多选题答案去重、标准化并进行集合比较；
- 等级按百分制计算，不再将原始分数直接和 80、90 比较；
- 证书编号改为密码学安全随机值；
- 活跃证书增加用户与考试维度的唯一约束；
- 移除包含正确答案和学生答案的生产调试日志。

### 4. 事务与数据库初始化

原代码在共享 SQLite 连接上分散执行 `BEGIN`、业务 SQL 和 `COMMIT`，并在业务请求中关闭外键检查。并发请求可能插入到同一事务之间，初始化 SQL 的多数错误也不会阻止服务启动。

整改后：

- 关键写入使用独立 SQLite 连接执行 `BEGIN IMMEDIATE`；
- 事务失败统一回滚；
- 不再为考试提交关闭外键检查；
- 初始化过程等待并检查全部 SQL；
- 启用 WAL、busy timeout 和常用索引；
- 增加 `schema_migrations` 基线表；
- 健康检查实际执行数据库查询；
- 测试可通过 `LAB_SAFETY_DB_PATH` 使用隔离数据库。

对于旧数据库，新增列和索引会幂等补充；旧表不会自动重建为带完整外键约束的新表，后续仍需正式的版本化表重建迁移。

### 5. 历史成绩稳定性

原成绩详情读取当前题库。如果管理员随后修改或删除题目，过去考试记录显示的题干、答案和解析也会变化。

整改后提交时保存题目快照，包括：

- 题干；
- 类型与分类；
- 选项；
- 正确答案；
- 解析；
- 用户答案和判定结果。

新记录优先读取快照；旧记录继续兼容读取当前题库。

### 6. 学生资料权限

学生原本可以通过个人资料接口修改姓名和院系。院系、班级参与考试发布范围判断，因此这等同于学生自行改变考试权限。

整改后：

- 学生只能修改手机号和邮箱；
- 姓名、学号、院系、班级和状态只能由管理员修改；
- 头像增加真实文件头校验；
- 新头像写入失败会清理临时文件；
- 更新成功后删除旧的受管头像文件。

### 7. 学习进度与 PDF 代理

原学习时长允许负数和异常大值，累加采用读后写方式，可能在并发请求下丢失。PDF 代理可以访问任意 HTTP 地址，存在访问本机、内网和云元数据地址的风险。

整改后：

- 进度必须是 0–100 的整数且不能倒退；
- 学习时长必须是正整数，单次最多 3600 秒；
- 进度和时长通过 SQLite UPSERT 原子更新；
- 只代理已经登记在学习资料表中的 URL；
- 拒绝 localhost、私网、链路本地、保留地址及私网 DNS 解析；
- 重定向目标重新验证；
- 限制连接时间、重定向次数、内容类型和 100MB 文件大小。

### 8. 管理端功能

- 考试创建和修改增加字段长度、时长、总分、及格线和题量校验；
- 空题目考试不能发布；
- 发布时同步真实题目数量；
- 发布范围去重并校验院系、班级真实存在；
- 考试记录导出由虚假静态地址改为真实 XLSX；
- 证书导出统一为受保护的真实 XLSX；
- 导出限制为 50,000 行，并防止表格公式注入。

### 9. 启动与关闭

- Express 应用构造和网络监听分离，测试导入不会自动占用端口；
- 生产配置在监听前验证；
- 增加 SIGTERM/SIGINT 优雅关闭；
- 请求 JSON 无效、请求体过大和 CORS 拒绝返回明确状态码。

## 自动化测试

后端使用 Node.js 20 内置 `node:test`，无需新增测试框架依赖。测试启动真实 Express 服务并使用临时 SQLite 数据库，覆盖：

- 数据库健康检查；
- 公共轮播和公告路由只读；
- 管理接口无令牌返回 401；
- 学生不能修改院系和姓名；
- 考试详情、开始和提交均执行发布范围校验；
- 3 道题、100 总分的满分回归；
- 多选题顺序和重复项标准化；
- 通过后禁止重复提交；
- 三次失败后的次数限制；
- 题库修改后历史记录保持原样；
- 学习进度单调、时长校验与累加；
- 未登记 PDF 地址在发起网络请求前被拒绝；
- 旧明文密码首次登录后升级为 scrypt；
- 管理端考试参数校验和空考试发布限制；
- 考试记录与证书真实导出；
- 畸形密码哈希、图片文件头和私网地址识别；
- 完整流程结束后 `PRAGMA foreign_key_check` 无违规。

CI 中后端测试为阻塞步骤。测试失败时不会构建和发布生产部署包。

## 仍需处理

### 公网部署前

1. 升级或替换存在高危漏洞的运行时依赖，重点包括 `multer`、`xlsx` 和 SQLite 相关依赖链；
2. 确认并清理历史提交中的学生 Excel 或其他真实个人信息；
3. 将浏览器 JWT 从 `localStorage` 迁移到安全 Cookie，并加入 CSRF 防护；
4. 为数据库建立真正按版本执行、可演练回滚的表重建迁移；
5. 增加异地备份、磁盘监控和恢复演练。

### 下一批代码质量

1. 将体量过大的 `adminController.js` 拆分为用户、考试、题库、记录、证书和设置模块；
2. 删除其中已经不再被路由使用的旧硬编码登录、明文密码导入和旧重置实现；
3. 为题库导入、自动抽题、删除级联和数据库恢复补充专项测试；
4. 修复两个前端项目现存 TypeScript 错误，并将类型检查改为阻塞 CI；
5. 增加 Playwright 浏览器测试，覆盖登录、学习、考试、证书和后台管理主流程。
